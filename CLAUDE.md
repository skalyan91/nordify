# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

**Wallpaper Ricer** is a Python CLI pipeline that prepares wallpapers in any of several fixed colour schemes (Nord, Solarized, Gruvbox, Everforest, Catppuccin, Dracula, ... — `palettize.PALETTES`). `depth_blur.py` handles cropping and depth-guided blur; `palettize.py` handles palette conversion. `entropy_crop.py` is a standalone utility for choosing a crop offset algorithmically instead of via `--align`.

## Setup and Usage

```bash
source venv/bin/activate

# Step 1 — crop + depth-guided blur
python3 depth_blur.py <input> -o <blurred> [--aspect W:H] [--align ...] [--blur PCT] [--focus D|auto]

# Step 2 — palettize
python3 palettize.py <blurred> -o <output> [--palette NAME] [--dither fs] [--mix [spectral|additive]]

# Optional — pick a crop offset that minimises edge-cutting entropy, apply to N images at once
python3 entropy_crop.py <edge_source> --aspect W:H <in1> <out1> [<in2> <out2> ...]
```

Core dependencies: `numpy`, `opencv-python-headless` (in `venv/`).  
Depth estimation: `transformers`, `torch`, `torchvision` (required by `DepthProImageProcessor`), `pillow` (downloaded on first run from HuggingFace).  
Optional: `mlx` (Apple Silicon) — required for `--mix`; accelerates blur pyramid in `depth_blur.py`.

## Architecture

Two scripts: `depth_blur.py` (preprocessing) and `palettize.py` (palette conversion, parametrised by `--palette`; see `PALETTES` for the full scheme list).

### Colour pipeline

- **`_srgb_to_linear` / `_linear_to_srgb`** — piecewise sRGB gamma (IEC 61966-2-1).
- **`_linear_rgb_to_oklab` / `_oklab_to_linear_rgb`** — Björn Ottosson's Oklab matrices via the LMS cube-root intermediate.
- **`_bgr_to_oklab` / `_oklab_to_bgr`** — OpenCV BGR ↔ Oklab, handling channel order and float normalisation.

### Palette

**`PALETTES`** — dict of named colour schemes (`nord`, `solarized-dark`, `gruvbox-dark`, `everforest-dark`, `catppuccin-mocha`, `dracula`), each a list of `(B,G,R)` uint8 triples with a pure black `(0,0,0)` prepended (extends the lightness range for `--mix`, regardless of how dark a scheme's own darkest tone is). `DEFAULT_PALETTE = 'nord'`; `_palette_bgr(name=None)` resolves a name to its colour list, raising a clear error for an unknown one. Every conversion/mixing entry point (`build_lookup`, `_fit_palette_ks`, `mix_convert_spectral`, `mix_convert_additive`) takes an explicit palette rather than reading a module-level constant, and `mix_convert_spectral`'s fitted-K/S cache (`_PALETTE_KS_CACHE`) is keyed by palette name so switching palettes across calls never reuses a stale fit.

**`_fit_palette_ks()`** — fits a reflectance spectrum to each palette colour. Spectral colours (single dominant channel) get a single Gaussian `R_base + A·exp(−(λ−λ₀)²/2σ²)`. Extra-spectral colours (purple/magenta: `g < r AND g < b`) use a **bi-Gaussian** with one red lobe (λ ∈ [560, 700] nm) and one blue/violet lobe (λ ∈ [400, 490] nm) — physically necessary because purple cannot be produced by any single wavelength.

**`build_lookup()`** — converts each palette entry to Oklab `(L, a, b)` and Oklch hue `H = arctan2(b, a)`; called once at startup.

### Conversion (`convert`)

For every pixel: BGR uint8 → Oklab `(L, a, b)` → Oklch chroma `C = sqrt(a²+b²)`.

The hue is snapped: the palette entry chosen by the dithering mode determines `H_out`; the output colour is reconstructed as `(L, C·cos(H_out), C·sin(H_out))` — preserving the pixel's own lightness and chroma while adopting a palette hue.

### Dithering modes

**No dithering (default)** — nearest palette entry by 3D Oklab distance; its hue is applied.

**`--dither fs`** — Floyd-Steinberg error diffusion in `(a, b)` space. Sequential pixel scan; error weights 7/16, 3/16, 5/16, 1/16. A `(thresh − 0.5) × scale` offset (scale = RMS palette chroma spread) is added to `(a_eff, b_eff)` before each palette lookup, seeding the diffusion with blue-noise statistics.

### Blue-noise threshold texture

**`_gen_blue_noise(size=64)`** — void-and-cluster algorithm (Ulichney 1993) using FFT convolution. Generated once on first use; cached in `_BN_TEXTURE`.

**`_threshold_texture(rows, cols)`** — tiles the blue-noise texture to image size.

### Palette mixing (`--mix`)

Two interchangeable models, both MLX-only and both leaving in-hull/in-simplex pixels unchanged.

**`--mix spectral` (default) — `mix_convert_spectral(image)`.** Fits a Gaussian (or bi-Gaussian) reflectance spectrum to each palette colour via `_fit_palette_ks()`, then for every pixel optimises a simplex of weights (Σcᵢ = 1) over the palette's K/S spectra to minimise Oklab distance to the target, mixing via Kubelka-Munk. Builds an augmented palette (pure colours + all pairwise 50/50 K/S mixtures), snaps each pixel to the nearest augmented entry, blurs, and re-snaps to seed the simplex weights before a phased Adam optimisation (`_mix_strip_spectral`) run strip-by-strip; `_simplex_project_mlx` projects onto the probability simplex after every step.

**`--mix additive` — `mix_convert_additive(image)`.** Convex hull of the palette in **linear RGB** (light/additive mixing), represented as half-spaces via `_halfspace_eqs(points)` (O(N⁴) brute force; fine for N ≤ 20 entries) — used only for the coarse in-hull membership test and the naive-clamp safety-net baseline below. `_halfspace_eqs` also returns each valid facet's vertex-index triple (`tris`); for a facet with more than 3 coplanar hull vertices, every valid triple of its vertices is emitted as its own (overlapping) triangle, and their union still covers the whole facet (any fan triangulation from one vertex is itself a subset of "all triples"). Its per-triple validity check orients the candidate normal outward from the point-set centroid *before* testing whether every point lies on the non-positive side — checking the other order silently drops real facets whenever the raw cross product's handedness (fixed only by the arbitrary `i<j<k` loop order) happens to point inward: confirmed on this palette, that ordering bug cut the hull from its true 24 facets down to 10, and the missing 14 included ones close enough to the typical highlight/midtone region that both the old and new optimisers below could converge to points measurably (~0.02 Oklab units) outside the true gamut before it was fixed.

Per pixel (`_face_newton_closest`, called from `_mix_strip_additive`), out-of-hull colours are moved to the Oklab-nearest point on the hull surface directly, via Levenberg-Marquardt-damped Gauss-Newton on each facet's own 2-parameter surface, rather than gradient descent over the whole hull. A hull triangle `(V0, V0+U, V0+W)` in linear RGB parametrises as `c(a,b) = V0 + a·U + b·W`; its LMS coordinates are affine in `(a,b)` since the RGB→LMS step is linear, so its Oklab position `X(a,b) = B · cbrt(L0 + a·P + b·Q)` is a smooth surface — flat before the cube root, curved after. The closest-point condition (residual `X(a,b) − target` orthogonal to the surface's own tangent plane) is transcendental in `(a,b)`, with no closed form via radicals, but each Gauss-Newton step is: build the 2×2 Gram matrix of the tangent vectors `X_a, X_b` (the surface's first fundamental form `E, F, G`) and solve the 2×2 normal equations by explicit matrix inverse. Near a facet's own corners the two tangent vectors can become nearly parallel (confirmed: `cos(angle(X_a, X_b)) ≈ 0.986` at one tested vertex), making the raw 2×2 system ill-conditioned — the undamped solve produced steps over 1000× too large, in the *wrong* direction, and got stuck on that corner for every subsequent iteration. Levenberg-Marquardt diagonal damping (`E → E(1+λ)`, `G → G(1+λ)`, fixed `λ = 1`, no annealing schedule — an earlier attempt at decaying `λ` left the first, worst-conditioned steps too small to escape the corner before `λ` had decayed) fixes this: as `λ` grows the system decouples toward plain gradient descent, always a valid descent direction regardless of conditioning. `(a, b)` are re-clamped to the facet's barycentric simplex after every step (reusing `_simplex_project_mlx` on the triple `(a, b, 1−a−b)`), so the search never leaves the triangle — this also handles points whose true nearest facet-location is on an edge or vertex, without separate edge/vertex cases. The initial `(a, b)` guess is the flat linear-RGB least-squares projection onto the triangle's own plane (closed form, ignoring the cube-root warp entirely) — confirmed necessary: starting instead from the facet centroid converged to a visibly worse point on at least one ill-conditioned test facet. The best result across all facets (24 for this palette) is picked per pixel by final Oklab distance. A safety net (compare against the naive hull-clamp baseline, keep whichever is closer) guards the same near-black numerical-instability case the previous optimiser guarded.

Validated against the previous two-phase-Adam optimiser (luminance, then chrominance, each phase gamut-projected after every step, ~300 iterations) on a same-palette test image: mean Oklab distance to target across touched pixels was *lower* with the facet-Newton approach (the old optimiser's own worst-case gap and its systematic advantage on some pixels both turned out to be it exploiting the same missing-facet gamut leak fixed above), and per-strip wall time was ~3.7× faster even though the corrected hull has more than double the facet count.

### Nighttime pre-processing (`--night`)

**`_nighttime(image, amount=1.0, light_boost=0.2)`** — darkens and cools the image in Oklab before palette conversion, continuously over `amount ∈ [-1, 1]` rather than as a fixed on/off effect: `L → 1 − (1−L)^p(amount)` (`p(amount) = 2^-amount`; at `amount=1`, `p=0.5` reproduces the original fixed curve `1 − √(1−L)`, a curve that darkens mid-tones and highlights while keeping shadows from crushing to black) and `b` shifted toward blue by a power `q(amount) = 2^amount` applied to normalised `b` and blended in inverse proportion to `L` (at `amount=1`, `q=2` reproduces the original fixed shift — dark pixels get the full squaring toward blue, bright pixels are left unchanged, so highlights keep their original colour temperature). `p` and `q` are reciprocal powers of the same base, so `amount=0` is the identity on both formulas (p=q=1) and `amount=-1` is their algebraic mirror — an "extreme day" push that brightens (`p=2`, i.e. `L → 1−(1−L)²`) and warms (`q=0.5`) exactly where the night direction would have darkened/cooled most (the shadows), continuously through zero rather than as a separate crossfaded effect. Light-peak protection (below) is scaled by `max(amount, 0)`, so it fades out approaching `amount=0` and plays no role at all on the day side — there's nothing to protect a peak *from* when brightening. Both base formulas' `amount=1` behaviour is unchanged from the original fixed implementation — an intermediate version tried protecting vivid-but-dim pixels (e.g. a lit window that isn't literally bright) by blending brightness protection with a chroma-derived signal, but any formulation that lets chroma influence the *same* protection signal as lightness ends up double-counting brightness protection for pixels where lightness alone is already high (most of an ordinary bright, sunlit photo), broadly under-darkening the whole image, not just genuinely vivid content — confirmed: mean lightness after the transform dropped only half as much on a bright test photo under such a design as under the original formula. Reverted in favour of a structurally separate mechanism (below) that leaves the base formulas untouched.

**`_dog_light_peaks(L, sigmas=(2.5, 4.0, 6.0, 10.0, 16.0, 24.0), threshold=0.12)`** — finds compact spots substantially brighter than their immediate surroundings (lit windows, streetlights, the moon) via multi-scale Difference-of-Gaussians blob detection on the lightness channel, the same core mechanism behind SIFT keypoints. A DoG level `blur(σᵢ) − blur(σᵢ₊₁)` is large and positive at the centre of a bright blob sized between σᵢ and σᵢ₊₁: the narrower blur still mostly reflects the blob's own bright value there, while the wider blur has averaged in more of the darker surround. Chosen over a segmentation-based alternative (e.g. SAM masks scored by inside-vs-surrounding-ring contrast) for being far simpler while measuring exactly the same underlying signal — local contrast is what makes something read as "a light," not any absolute colour value — with no ML model, depth map, or extra dependency needed.

A peak must be a local maximum both spatially (its own 3×3 neighbourhood, via dilate-and-compare) and across scale (versus the adjacent DoG level), then clear an absolute `threshold`. Both matter: dropping the scale check would count the same physical light several times over at adjacent scales; dropping the spatial check would accept plain edges and gradients, which have elevated DoG response over an extended region but no compact spatial peak. `sigmas` deliberately starts at 2.5px, not smaller — confirmed on a photo of glossy leaves that including a sub-2px scale finds mostly small specular highlight glints (81% of all detected peaks sat at the smallest scale tested), not real lights; dropping it removed nearly all of that noise there while every genuine light in a separate test photo (a painting with distant town lights and a moon) stayed detected. `threshold=0.12` was picked the same way: on that painting, real lights' own peak values formed a cluster (0.16–0.22) clearly separated from weaker peaks running along painted silhouette edges and canvas-texture brushwork.

**`_light_protection_map(shape, peaks, spread=1.5, strength_scale=3.0)`** — turns detected peaks into a soft (H, W) map in [0, 1]: each peak becomes a Gaussian bump centred on it, sized to `spread` × its own detected scale (wider than the core so protection feathers out rather than cutting off sharply) with amplitude proportional to DoG strength (capped at 1). Overlapping bumps combine via `maximum`, not addition, so a light detected at more than one adjacent scale doesn't get over-protected. Only evaluates each peak's own local neighbourhood, not the whole image, since a busy photo can have tens to low hundreds of peaks.

In `_nighttime`, this map blends the darkening/blue-shift formulas toward "unaffected, and boosted `light_boost` brighter" at detected light locations — a structurally separate step layered on top of the untouched base formulas, rather than a modification to their own protection logic.

## depth_blur.py

Preprocessing script: crop → depth estimation → depth-guided blur.

### Cropping

**`_crop_to_aspect(image, ratio_w, ratio_h, align='center')`** — crops to the given aspect ratio. `align` is `'left'`/`'center'`/`'right'` when width is cropped, `'top'`/`'center'`/`'bottom'` when height is cropped. Run by default; skip with `--no-crop`.

### Depth estimation

**`_estimate_depth(image_bgr, model, tile_width_frac, tile_overlap)`** — runs Depth Anything V2 Small (`depth-anything/Depth-Anything-V2-Small-hf`, the default) via the HuggingFace `transformers` pipeline (MPS on Apple Silicon, CPU otherwise). Depth Anything is a fixed-input-size model — its image processor resizes everything down to a small fixed size (e.g. 518px) regardless of source resolution — so a single whole-image ("global") pass destroys thin foreground structures (wires, masts, lattice towers) before the network ever sees them, and silently inherits whatever's behind them in the depth map. `_estimate_depth` recovers that detail with **`_tile_refine`**, run multiple times at different footprints and combined by taking the per-pixel maximum:

**`_tile_refine(rgb, infer_fn, reference, native_tile, footprint, overlap_frac)`** — one tiled refinement pass. Crops overlapping tiles sized to `footprint` (downsampled to the model's native input resolution — `native_tile`, e.g. 518px — if `footprint` is larger), each least-squares fit (`np.linalg.lstsq`, subsampled 4×4) — scale + shift — to `reference`'s own values in its footprint, since a depth model's output is only defined up to an unknown per-inference affine transform (it's trained with a scale/shift-invariant loss). **`_tile_starts(length, tile, stride)`** computes 1-D tile offsets snapped flush to the far edge, and **`_feather_weights(start, length, total, overlap)`** produces 1-D tent weights (ramping 0→1/1→0 only on sides with a neighbouring tile, full weight to the image border otherwise) whose 2-D outer product blends each tile's contribution into a shared accumulator — the same premultiplied-accumulate-then-normalise pattern `_depth_blur` uses for its slabs.

`_estimate_depth`'s default `tile_width_frac = [0.5, 0.25, 0.125]` runs three such passes, each sizing its tile *footprint* as that fraction of the image's width (larger than native resolution, so each tile is downsampled before inference) and each aligned directly against the global pass, not chained through each other. The final map is `np.maximum` across the global pass and all three — **not** an average or a cascade. Different footprints have different blind spots that don't overlap much, and max lets each pass contribute only where it's more confident something is close, without any pass's mistake erasing another's correct detail:

- A wide pass (`0.5` — footprint spans half the image) gives smooth, internally consistent depth on solid objects — confirmed: a power-station smokestack's per-row disparity that wobbled non-monotonically by ±15/255 with a single native-zoom pass became visually uniform top to bottom. But it blends soft, semi-transparent things (steam, smoke) into the sky behind them, and past roughly a 2.5x per-tile downsample it loses thin wires outright.
- A narrow pass (`0.125`, close to native resolution) keeps fine detail that wide passes lose — confirmed: a lattice transmission tower's individual crossing struts, an unresolved blur at `0.5`, are fully resolved at `0.125` — but is noisy on large solid objects the same way a lone native-zoom pass always was.
- Averaging or chaining (tried first) doesn't work: two sources with the *same* blind spot (e.g. global and a wide pass both failing to separate steam from sky) just average to another version of that blind spot, and a narrow pass forced to align against an already-wrong wide-pass reference inherits the mistake instead of correcting it. Max sidesteps both, since a correct, nearer reading from any single pass always wins regardless of what the others say.

Earlier, Apple's Depth Pro (`apple/DepthPro-hf`) was the default — a multi-scale ViT that derives patches from multiple downsamplings of the *original* image internally, so a single pass sees fine detail without any tiling at all. It's still available via `--model apple/DepthPro-hf` and `_estimate_depth` still special-cases it (`"DepthPro" in type(pipe.model).__name__`, converting its metric depth in metres to disparity via `1 / depth` and skipping the tiling path entirely, since tiling measurably doesn't help it). It was dropped as the default because on stylised/painted art specifically it can misjudge large flat regions (see `--fix-sky` below) in a way Depth Anything V2 doesn't, and — with the multi-pass tiling above — Depth Anything now matches or exceeds it on thin-structure detail too.

Output is always `(H, W)` float32, disparity convention (higher = closer/foreground).

### Sky depth correction (`--fix-sky`)

No longer needed by the default pipeline — this was specifically a Depth Pro correction, and Depth Anything V2 (the new default) doesn't make the mistake it corrects. Still available and functional via `--fix-sky` for anyone using `--model apple/DepthPro-hf`.

Depth Pro, trained on real photographs, can read a flat, desaturated, silhouette-like region as *near* — a strong learned cue for atmospheric haze in photos — even when it's the sky sitting behind a much nearer, plainly-painted structure. Confirmed on a power-station painting: Depth Pro placed the sky at disparity 0.11 and the building in front of it at 0.08 (sky nearer — backwards), while Depth Anything V2 placed them at 0.11 and 0.40 respectively (correct) on the same image. This is an out-of-distribution failure specific to stylised/painted content, not a general flaw in Depth Pro (it's still clearly better for thin structures) or in this pipeline's disparity handling (the same maps put foreground grass at the correct, unambiguous near end in both cases).

**`_otsu_sky_mask(disp, feather=3.0)`** — segments the farthest, most tightly-clustered region of a disparity map (typically sky) via Otsu's threshold, which picks the split minimising intra-class variance — effective here since sky sits in a narrow low-disparity band clearly apart from a scene's much wider spread (measured: sky std ≈ tight cluster around a mean of ~11/255 vs. a scene spanning 14–232). Returns a feathered `(H, W)` float32 mask (1 = sky) so a hard per-pixel threshold doesn't stairstep the blend seam.

**`_fix_sky_depth(depth_disp, image_bgr, sky_model=...)`** — runs Depth Anything V2 (via `_estimate_depth`, so it goes through the tiled-refinement path above) purely to locate and correct the sky: `_otsu_sky_mask` segments its map, then Depth Anything's sky-region values are least-squares fit (scale + shift) to `depth_disp`'s scale using the *non-sky* region — never the sky region itself, since fitting sky-to-sky would just reproduce whatever's wrong with `depth_disp`'s own sky values — before being blended into `depth_disp` through the feathered mask. A final safety clamp caps the corrected sky at the minimum non-sky disparity, guaranteeing it reads as at least as far as everything in front of it even if the fit is imperfect. Wired into `depth_blur.py`'s CLI as `--fix-sky`; doubles depth-estimation cost (Depth Anything's tiled pass runs in addition to Depth Pro's global pass) but that's still negligible next to `palettize.py --mix`'s per-image runtime.

### Mast depth flattening (`--flatten-masts`)

Superseded by `_estimate_depth`'s own multi-pass max combination for the default model — a `0.5`-footprint pass already gives smokestacks smooth, internally consistent depth directly, without needing SAM segmentation afterward. Still available and functional via `--flatten-masts`.

Both Depth Pro and Depth Anything V2 can render a thin, tall, rigid vertical structure (a power-station smokestack) with substantial internal depth noise along its height — confirmed non-monotonic wobbles of ±15/255 with no plausible perspective explanation for an object whose true depth barely varies top to bottom.

**`_flatten_thin_masts(depth_disp, image_bgr, sam_model=..., target_width=1500, min_aspect=2.0, min_height_frac=0.05, max_relative_spread=0.15, feather=2.0)`** — finds candidate masts via SAM's automatic mask generation (the `mask-generation` pipeline) on the *source image*, not any depth map: using a depth map to find its own errors is circular, and an Otsu split on either model's map here lumps the (fairly dark) smokestacks in with sky rather than isolating them. An earlier classical approach (black-hat/top-hat contrast + connected components, filtered by aspect ratio and solidity) worked but was unreliable — it could only separate a mast from a *locally uniform* backdrop, missing one entirely when it was embedded in busy, high-contrast painted clouds.

Each surviving mask's depth is *not* flattened to a single value outright — a mast large enough to show genuine perspective drift across its height would lose that real variation. Each pixel's deviation from the mask's own median is instead clamped to a tolerance band (a soft winsorize, not a hard replace): deviations already inside the band pass through untouched, and only the excess beyond it — the part with no plausible perspective explanation — gets pulled in. That band shrinks quadratically, not linearly, toward the background: disparity is proportional to inverse distance, so for a mast of fixed real-world height, the disparity range its own top-to-bottom depth difference could plausibly produce shrinks with the square of distance, not linearly — a mast twice as far away should be allowed a quarter of the tolerance, not half. `allowed = max_relative_spread * median_val * (median_val / scene_max)`: at `median_val == scene_max` (the nearest thing in the whole scene) it reduces to the old linear `max_relative_spread * median_val`, and falls away quadratically for anything farther back (measured: full 15% tolerance at the scene's nearest point, ~2% for a background-level smokestack).

The clamp is also one-sided: only deviations reading *farther* than the mask's own median are pulled in (`np.maximum(depth_disp - median_val, -allowed)`, no upper bound); a mask can't have something genuinely farther "through" it, so an excess-far pixel is unambiguous noise, but a pixel reading *nearer* could be something real crossing in front of it — confirmed necessary: a transmission wire passing in front of a smokestack was getting its correct, nearer depth erased and pulled back to the smokestack's own median before this was one-sided.

The image is downsampled to `target_width` before running SAM. SAM's ViT encoder resizes to a fixed internal resolution regardless of input size, so running it on the full-resolution source doesn't improve mask quality at all — confirmed empirically, full-resolution and a 1500px-wide downsample of the same image produce the *same* mask overlap against the true mast shape (~0.6) — it only makes every downstream step of automatic mask generation (per-point decoding, mask upsampling, NMS across ~1000 candidate masks) far more expensive for no benefit: ~17 minutes for one 4500px-wide image vs. ~17 seconds downsampled, a ~60x difference for identical output. Each mask's own bounding-box aspect ratio is enough to keep just the mast-like ones — no solidity check is needed the way the classical approach required one, since SAM's masks already respect real object boundaries: the transmission tower's wire lattice isn't returned as any tall/narrow mask in the first place (confirmed empirically — zero overlap between the tower region and any aspect-qualifying mask). This version fixed *both* smokestacks tested (including the one against busy clouds that defeated the classical approach), each in a few seconds.

### Automatic figure detection (`--focus auto`)

Picks the focus plane automatically by locating the principal "figure" — a compact foreground subject — instead of requiring a manually guessed `--focus` value.

**`_foveal_weight_map(h, w, viewing_distance_factor=1.5, e2_degrees=2.3)`** — the perceptual model "the figure" is now grounded in: an earlier version picked it via five hand-picked shape criteria (size, a compactness measure, convexity, connectedness, depth) combined by weights tuned reactively against whichever test image had just broken — a genuinely underdetermined procedure, since nothing but trial and error justified any particular weight. This version instead asks how sharply a viewer would actually resolve each pixel. The viewer is assumed to sit at `viewing_distance_factor` × the image's own diagonal and fixate on its centre (the only defensible default with no gaze data); a pixel `r` pixels from that centre subtends `arctan(r / (viewing_distance_factor · diagonal_px))` of visual angle — note the unknown physical pixel pitch cancels out of that ratio entirely, so no assumption about actual display size is needed. Acuity then falls off with eccentricity via the standard cortical-magnification approximation `M(e) = M0 / (1 + e/E2)` (Rovamo & Virsu 1979; the same falloff underlies foveated-rendering work, e.g. Guenter et al. 2012), `E2 ≈ 2.3°` — a smooth gradient with no free radius to tune, unlike a Gaussian.

**`_detect_figure_focus(depth_raw, image_bgr, sam_model="facebook/sam-vit-base", target_width=1500, min_area_frac=0.0005, max_area_frac=0.5, viewing_distance_factor=1.5, e2_degrees=2.3)`** — "the figure" is whichever segmented region has the greatest total *resolvable* area under the model above — one principled quantity replacing five arbitrarily-weighted ones. Candidates still come from SAM's automatic mask generation on the *source image*, the same trade `_flatten_thin_masts` already makes and for the same reason (an earlier version ran classical Canny edge detection on the depth map directly and failed on a stylised power-station painting, where the depth map's silhouette gradient had gaps too small to see by eye but large enough to leave the whole frame as one undifferentiated region — SAM segments from the image's own unambiguous visual boundaries instead). The image is downsampled to `target_width` first, exactly as `_flatten_thin_masts` does (same ~60x cost/no-quality-loss trade).

A single object can still come back as several SAM masks (hierarchical output; an occluder can split one). Regions whose depth ranges (10th–90th percentile of their own pixels) overlap by more than 50% of *both* ranges' own extents (**`_ranges_overlap_50`**) are merged via union-find (**`_UnionFind`**). Matching depth alone says nothing about spatial contiguity, though — a scene full of similar-depth clutter (leaf clusters scattered through a tree canopy) can merge into one large but disconnected union — so each merged union is split back into its connected components before scoring, and each component becomes its own candidate. This guarantees every scored candidate is one spatially contiguous piece, without reintroducing a scored shape preference the way the old connectedness criterion was — it's just the baseline requirement that a candidate be *a* region, not a scattered union of several. Unlike the earlier version, a region touching the image border is *not* specially excluded: that exclusion only protected shape criteria (aspect ratio, convexity) that this version no longer has: a partially-visible figure's true weighted mass is merely underestimated by whatever's cropped off, like any other area-based measure applied to a partial view.

Nearness is folded into the *same* per-pixel weight as a second multiplicative factor — normalised disparity, `(depth_raw − d_min) / (d_max − d_min)`, 0 at the scene's own farthest point and 1 at its nearest — rather than scored as a separate ranking criterion. Confirmed necessary: without it, a large, cleanly-segmented but *distant* region (a patch of sky) can out-score every closer subject on spatial extent alone, since nothing otherwise distinguishes a near subject from a far one — an orange tree's sky won outright over its actual fruit and foliage before this was added. This needs no extra free parameter beyond the depth map's own range, and is a smooth gradient like the foveal falloff, not a hard near/far cutoff.

`min_area_frac` is a cheap early filter for SAM's smallest sub-part proposals (not correctness-critical: a truly tiny region loses on total weighted mass anyway, since weight is capped at 1.0/pixel). `max_area_frac` (50%) is still load-bearing: a background region can span the frame's highest-weight central pixels too, and its far larger total area can still out-mass a real bounded subject — exactly the failure mode this catches. Falls back to `d_focus=0.0` (background/infinity, the module's pre-existing default) if no candidate survives.

Wired into the CLI as `--focus auto` (alongside the existing numeric `--focus D`); `--save-figure-mask PATH` saves the winning candidate's mask alongside the main output, for debugging.

### Depth-guided blur

**`_make_disc_kernel(radius)`** — builds a normalised uniform disc (pillbox) kernel with a 1-pixel anti-aliased edge ramp (`clip(radius − dist + 0.5, 0, 1)`). Returns a 1×1 identity when `radius < 0.5`.

**`_disc_blur_mlx(img, radius)`** / **`_disc_blur_cpu(img, radius)`** — disc blur for `(H, W, C)` arrays (any C) on GPU via MLX 2-D depthwise `conv2d` (weight shape `(C, kH, kW, 1)`, `groups=C`) or CPU via `cv2.filter2D`. Both reflect-pad at boundaries.

**`_depth_blur(image, depth_raw, sigma_max, d_focus=0.0, n_levels=16)`** — **layered forward-scatter compositing**. Divides depth into K=`n_levels` slabs with tent-function membership (exact partition of unity). For each slab k (front-to-back order, foreground first): packs `image × mask_k` and `mask_k` as a 4-channel array, blurs with disc radius `rₖ = sigma_max · |dₖ − d_focus| / max(d_focus, 1−d_focus)` (telecentric CoC), then composites with premultiplied alpha (`color_acc += remaining · color_k`, `weight_acc += remaining · alpha_k`). Background bokeh circles at foreground edges emerge naturally from the forward scatter — no depth dilation needed. Un-premultiplies at the end (`result / weight_acc`). `--depth-only` saves the blur-strength map `|d − d_focus| / denom` (white = max blur, black = in-focus plane); `--save-depth` saves the plain normalised depth map (no focus-relative transform) alongside the main blurred output.

## entropy_crop.py

Standalone utility: picks a crop offset that minimises the entropy of the image content it would cut, then applies that offset to one or more pixel-aligned images. No depth map needed — runs Sobel edge detection directly on the "edge source" image.

**`_gradient_magnitude(image_bgr)`** — continuous Sobel gradient magnitude (after a light Gaussian blur), not a thresholded edge detector like Canny — a palette-snapped image is mostly large flat colour regions, where Canny goes nearly empty and leaves pathological ties between candidate offsets.

**`_edge_risk_kernel(new_length, other, viewing_distance_factor=1.5, e2_degrees=2.3)`** — `depth_blur.py`'s parafoveal acuity model (see `_foveal_weight_map`/`_detect_figure_focus` there) applied in reverse. That model gives a pixel's *acuity* as `1 / (1 + e/E2)` (Rovamo & Virsu 1979 cortical magnification), where `e` is its eccentricity in degrees from a viewer fixating the image's own centre. Here the wanted quantity is the opposite — not how well a viewer would see a position, but how much is lost if it's cut — the complement `e / (e + E2)`: 0 at the crop window's own centre (most sharply seen, so losing it is most noticeable), rising smoothly toward 1 at the boundary (already at the edge of clear vision, so costs little to lose). This replaces an earlier purely geometric parabola of the same 0-at-centre, rising-to-boundary shape, but with no arbitrary exponent chosen — only quantities with an independent, citable meaning (assumed viewing distance, half-acuity eccentricity). Eccentricity is derived from crop-axis position only (not the perpendicular axis), matching how the parabola it replaces also only ever varied along the crop axis.

**`_correlate_valid(m, kernel)`** — batched 'valid'-mode cross-correlation of every row of `m` against a fixed `kernel`, via FFT (`np.fft.rfft`/`irfft`, batched across rows in one transform). A direct sliding-window sum per candidate offset would cost O(excess × new_length × other) — potentially billions of operations for a large image — since `_edge_risk_kernel`'s shape (unlike the old parabola) isn't a polynomial in position and so can't be expanded into O(1)-per-offset prefix sums; FFT convolution restores efficiency (O(other × L log L)) for an arbitrary kernel shape.

**`find_crop_offset(edge_source, ratio_w, ratio_h)`** — crops whichever axis the target ratio requires narrowing (same width-vs-height test as `depth_blur.py`'s `_crop_to_aspect`). For each candidate offset, scores the crop by the entropy of the gradient magnitude across the *entire* kept window, not just the single boundary row/column, weighted by `_edge_risk_kernel` and summed via `_correlate_valid` for every offset at once. Treating that weighted gradient magnitude as an unnormalised distribution over rows/columns, low entropy means the cut is concentrated (mostly flat, featureless, only clipping something in a narrow span) rather than smeared across many different rows/columns, i.e. many different objects; cutting nothing scores zero. Ties (common at zero entropy) break on total edge weight cut, ascending.

**`main()`** — reads one edge-source image, computes the offset once via `find_crop_offset`, then applies `_apply_crop` identically to every `<in> <out>` pair given (asserting each input is pixel-aligned with the edge source) — so a day/night pair of the same wallpaper crops in lock-step. `--visualize` dumps the edge source with the chosen crop boundaries (red) drawn on it, for sanity-checking.
